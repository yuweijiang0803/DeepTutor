# 学生学习中心产品主轴（STUDENT LEARNING CENTER）

> 定位：**初中学生学习中心**——不是 AI 工作台，是学生每天回来学习的地方。
> 一份共识文档：定位 / 画像 / 首页 IA / 核心闭环 / 数据主轴 / 待定项。
> 关联文档：`LEARNING_ADVISOR.md`（顾问/付费）、`CLASS_MODEL.md`（班级层）、`SUBJECT_PACK.md`（初中数学内容）。

## 一、定位一句话

给初中学生一个**围绕"今天该学什么"展开的学习中心**：
学生绑定教材进度后，AI 带着他同步学、补错题、冲刺复习，数据沉淀成学生档案，
家长通过分享链接查看学情报告。**学生是日常主角，家长是付费人。**

## 二、用户画像（首版聚焦）

| 角色 | 画像 | 诉求 |
|---|---|---|
| **学生（主角）** | 7~9 年级，人教版起步；半自觉，作业/考前紧张/家长催才动；知道自己"函数不行"但说不清为什么 | 今天不会的搞懂别留到考试；考前知道抓什么 |
| **家长（付费人）** | 妈妈 36~45，白天上班晚上盯作业；不懂学科细节 | 有人替我看住孩子学得怎么样、弱点在哪；便宜过机构 |
| **老师/班主任（B端渠道）** | 复用学校班级体系 | 布置 + 班级学情（后置） |

## 三、已定决策链

| 维度 | 决策 |
|---|---|
| 学段 | 初中先行（7~9），后续向小学/高中复制 |
| 学科 | 骨架全开：数学深、语/英可绑进度浅用（教材版本库人教版先行） |
| 首页 | 学科切换 × 模式平级：今日同步 / 错题攻坚 / 考前冲刺 / 自学 |
| 冷启动 | 学生自报：年级 + 教材 + 当前章节 |
| 首个闭环 | 今日同步（见下） |
| 同步课程 | 按**知识点**推进；每知识点由 **OpenMAIC 生成课件**（概念页/例题页/quiz），**DeepTutor 内播放**给学生看 |
| 账号 | 首版复用**小智账号**（学生单身份）；开放自注册后置 |
| 家长报告 | 首版做**分享链接/PDF**，不设家长独立端 |
| 渠道 | 首版学校/小智渠道；C 端家长自购后置 |

> 现状核对：目前 `/register` 无 UI 入口且仅空库首启开放；线上只有小智 SSO + 管理员建号。
> "先用小智账号"= 零新账号基建，学生单身份天然契合。

## 四、首页信息架构（改造方向）

现状问题：`/space` 是**功能目录**（聊天/笔记本/题库/精通之路磁贴），主语是产品能力。
目标：首页主语换成**学生本人的状态**。

```
登录 → 学科切换（数学深 / 语英浅）
     → 模式平级入口
       今日同步：今日该学什么（教材进度推荐，默认主角）
       错题攻坚：哪儿弱补哪儿
       考前冲刺：考什么复习什么
       自学：自主探索
     → 学生档案投影：我的掌握度 / 错题 / 最近进步
```

> 预留升级：模式权重将来由数据驱动（错题堆积 → 错题攻坚置顶），首版平级即可，避免退回应功能陈列。

## 五、首个闭环（今日同步）

```
学生自报教材进度 → 定位当前知识点 → 打开 OpenMAIC 课件（该知识点：概念/例题/quiz 逐页播放）
→ 播放中穿插 quiz → 掌握度更新 / 错题入档 → 推进下一知识点（或回头补薄弱点）
```

- **粒度**：按**知识点**推进（沿用学科包 章→知识点 结构，不另设课时层）
- **内容来源**：每个知识点由 **OpenMAIC 按需生成**一份课件（粒度由生成需求决定，概念页 + 例题页 + quiz 页，讲解词在 speech），落库后学生播放
- **播放形式**：DeepTutor 内嵌播放器直接播（现已有 `openmaic_url` + watch 播放页基础），学生全程不离开
- 数据来源：精通之路（已有，改对接学科包 kp_id）+ 错题本（notebook_entries 雏形）
- 内容主干：初中数学学科包 `SUBJECT_PACK.md`（对齐人教版课标）

> OpenMAIC 是**内容生产工具**：章→知识点骨架由 DeepTutor 学科包定（教什么），
> 每知识点的"怎么讲"由 OpenMAIC 生成课件承担。产物落库即知识点的讲义+题目载体。
> 生产方式（老师单点触发生成 vs 批量自动生成）暂不锁死，先跑通"单点生成→播放"闭环。

## 六、数据分层（内容树 + 进度，分开存储）

```
【内容层 · 全局预置 · 新建 dt_subject_* 表】
dt_subject            学科（初中数学/人教版/七上…）
dt_subject_module     章（对齐教材）
dt_subject_kp         知识点（对齐课标）
  └─ 挂 openmaic 课件引用（stage id）+ 题目
dt_subject_question   题目
内容树全局共享一份，老师/管理员录入，长期稳定

【课件层 · OpenMAIC 侧 · 本体留在生成方】
OpenMAIC postgres 存 stage JSON（每知识点一份课件）
DeepTutor 只存引用（stage id / watch URL），播放时拉取
不双写；OpenMAIC 下线只影响播放不影响学习记录

【进度层 · 每个学生 · 复用精通之路】
dt_mastery_paths     学生学某学科 = 开一条 path
  └─ modules/kps 直接引用内容层 id（LearningModule.id = dt_subject_module.id，
     KnowledgePoint.id = dt_subject_kp.id），非 AI 现造
掌握度/错题可精确聚合到知识点 → 班级学情有底座
```

> 三者生命周期不同，不能混：内容一次录入多人引用、课件由 OpenMAIC 维护、
> 进度 per-user 持续变化。混进 `dt_mastery_paths` 会导致每个学生重复存整棵
> 学科树、内容更新全量同步，数据爆炸且无法做班级聚合。

## 七、数据主轴（护城河本体）

```
StudentProfile：教材进度 × 各科掌握度图谱 × 错题错因 × 学习风格
   ├── 投影给学生：今日计划 / 掌握度
   ├── 投影给家长：学情报告（分享链接）
   └── 投影给老师：班级学情（后置）
```

档案不是给学生"填表"看的页面，是**后台模型**，驱动首页推荐与报告。
现有代码只差聚合一步：精通之路掌握度、notebook 错题、persona/L3 风格是散的。

## 八、待定项（首版可不解决，但要占位）

1. **付费时点**：首版走学校渠道，是机构买单还是家长订阅？商业模式先写一句占位。
2. **语/英"可绑进度浅用"的底线**：只做同步题库，还是 AI 对话也算浅用？决定内容侧工作量。
3. **报告链接发给谁**：绑定家长手机号/微信？涉及隐私与发送方式。
4. **教材版本边界**：语文/英语版本多（人教/北师大/苏教…），首版是否锁人教版。
5. **"今日同步"是否依赖班级**：首版学生自报进度即可，不依赖老师布置（后置 dt_assignment）。
6. **OpenMAIC 课件→掌握度的闭环**：播放中/后的 quiz 结果如何回写精通之路的掌握度与错题——需要 OpenMAIC 侧进度/答题回传接口（INTEGRATION_PLAN §4 改造项②）打通。首版可先人工/粗略记录，精确回传后置。
