# PC 端数据本地化双模式方案（LOCAL_MODE）

> 目标：商业版 PC 客户端默认像开源版一样**数据全存本地、免登录、用户自带 LLM key**；
> 用户可勾选"开启同步"，登录 XiaoZhi 后切换到**现有商业版方案**（服务器 MySQL 集中存储）。
> 同一套代码、两种模式，默认路径零改动。

## 〇、已定决策（2026-08-26）

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 知识库（RAG）是否同步 | **不同步**，始终本地文件 |
| 2 | 记忆 / notebooks 是否同步 | **不同步**，始终本地文件（v2 按需再议） |
| 3 | 本地模式授权方式 | **暂时免费**（本地免登录，用于引流；同步/云服务为收费点） |
| 4 | 同步模式 LLM | 走学校服务器统一 key（学生自带 key + 服务器存储的组合暂不做） |
| 5 | 关闭同步的回迁 | 默认不自动回迁，提供"仅拉取"按钮由用户手动触发 |

## 一、背景与现状

### 1.1 现状存储分布

| 数据类型 | 存储位置 | 是否已本地化开关 |
| --- | --- | --- |
| 会话记录 | `get_session_store()` 工厂 → MySQL / SQLite | ✅ 已有 `mysql_configured()` 开关 |
| 错题本 | `get_learning_store()` 工厂 → MySQL / SQLite | ✅ 已有 |
| 精通路径 | 同上 | ✅ 已有 |
| 知识库（RAG） | 本地文件 `data/knowledge_bases/` | 天然本地 |
| 记忆 / notebooks | 本地文件 `data/` | 天然本地 |
| 设置 | 本地 JSON `data/user/settings/` | 天然本地 |
| 用户账号 | XiaoZhi 服务器（仅同步模式需要） | — |

### 1.2 关键结论

`mysql_configured()`（settings 里 `enabled + host` 同时为真时走 MySQL，否则回退 SQLite）
已经是现成的本地化开关——**不配置 MySQL 即纯本地，与开源版完全一致**。
desktop Electron 壳已存在（`desktop/`）。因此"PC 端本地化"技术底座已具备，主要工作是同步层与 UI。

## 二、双模式总览

| | 本地模式（默认） | 同步模式（勾选后） |
| --- | --- | --- |
| 登录 | 免登录 | XiaoZhi 账号登录 |
| 存储 | 本机 SQLite + 本地文件 | 服务器 MySQL（= 现有商业版） |
| LLM | 用户自带 key（settings 配置） | 服务器统一 key |
| 数据归属 | 只在本机 | 服务器（可跨设备、可被教师/校长查看） |
| 等价物 | 开源版 | 商业版 |

模式 = **存储后端切换**，不是新做一套。

## 三、数据存储映射

| 数据 | 本地模式 | 同步模式 |
| --- | --- | --- |
| 会话记录 | SQLiteSessionStore | MySQLSessionStore |
| 错题 / 精通路径 | LearningStore（SQLite） | MySQLLearningStore |
| 知识库（RAG） | 本地文件 | **本地文件（不同步，见 4.4）** |
| 记忆 / notebooks | 本地文件 | **本地文件（不同步，第一版）** |
| 设置 | 本地 JSON | 本地 JSON（LLM 指向服务器 key） |

## 四、模式切换与同步机制

> 第一版采用**迁移式切换**（而非实时双向同步）：
> 开启同步 = 登录后把本地学习数据一次性推送到服务器，之后读写全部走服务器；
> 关闭同步 = 回退本地存储。这最贴合"同步 = 现有商业版方案"的预期，工作量最小。

### 4.1 开关与登录门控

```
设置页："开启本地同步"开关
   ├─ 未勾选（默认）→ 本地模式，无需登录
   └─ 勾选 → 弹出 XiaoZhi 登录 → 校验通过 → 执行迁移 → 切到服务器存储
```

- 登录即隐含"数据要上云"的知情，符合"数据在哪、身份在哪"原则。
- 关闭同步时：若之前同步过，先询问"是否把服务器数据拉回本地"，确认后回迁再关闭。

### 4.2 开启同步（本地 → 云端一次迁移）

1. 登录 XiaoZhi，拿到用户身份（dt_user_id）
2. 对三类学习数据做全量迁移（复用现有 MySQL 存储的写入接口）：
   - 会话记录（MySQLSessionStore.upsert 系列）
   - 错题本（notebook_entries → MySQL）
   - 精通路径（mastery_* → MySQLLearningStore）
3. 迁移完成后，`mysql_configured()` 生效 → 读写自动切到服务器
4. 迁移是"上传合并"：服务器已存在同 key 记录时，以**时间戳新者胜**（last-write-wins），不覆盖新数据

### 4.3 关闭同步（云端 → 本地回迁，可选）

- 用户主动关闭：询问是否回迁 → 是则把服务器数据拉回本地 SQLite（同样 last-write-wins）
- 回迁后关闭 MySQL 配置，回到纯本地
- 不做自动回迁（避免误触导致数据分裂）

### 4.4 同步范围（第一版）

| 同步 | 数据 | 理由 |
| --- | --- | --- |
| ✅ 同步 | 会话 / 错题 / 精通路径 | 学习核心数据，跨设备 + 教师学情需要 |
| ⛔ 不同步（已定） | 知识库（RAG 文档 + 向量） | 体积大、个人资料属性强，上传成本高收益低；本地推理用本地库 |
| ⛔ 不同步（已定） | 记忆 / notebooks | 个人数据本地留存 |

### 4.5 冲突处理

- 第一版统一 **last-write-wins（按时间戳）**，不做字段级合并
- 迁移日志记录每类数据迁移条数 + 冲突覆盖条数，结束后在 UI 提示

## 五、LLM 配置

| 模式 | 谁提供 key | 实现 |
| --- | --- | --- |
| 本地模式 | 用户自带 | 沿用现有 settings 的 LLM 配置（provider/api_key/base_url） |
| 同步模式 | 学校服务器统一 | 客户端 LLM 调用指向学校服务器（或由服务器转发），本机不配 key |

- 本地模式切到同步模式时：LLM 配置切换为"服务器统一"，与存储切换一同完成
- 同步模式下的推理**数据仍走服务器**，客户端本地不留原始请求

## 六、UI 交互

### 6.1 设置页新增"数据存储"区块

```
数据存储
  [ ] 开启本地同步（数据保存到学校服务器，可跨设备）
      └─ 未开启：数据仅保存在本机，无需登录
```

- 勾选 → 登录弹窗（复用现有 XiaoZhi 登录）
- 开启/关闭时显示迁移进度（"正在上传 128 条错题记录…"）
- 完成后 toast 提示迁移结果

### 6.2 启动行为

- 本地模式：无登录要求，直接进入（如开源版）
- 同步模式：启动时校验 token 有效性，失效则引导重新登录

## 七、技术改动清单

1. **存储工厂扩展**：`get_session_store()` / `get_learning_store()` 已按 `mysql_configured()` 切换，无需改动核心逻辑；新增"模式"设定写入 settings
2. **迁移服务**（新增，`deeptutor/services/sync/`）：
   - `migrate_local_to_server(user_id)`：读 SQLite → 写 MySQL
   - `migrate_server_to_local(user_id)`：读 MySQL → 写 SQLite
   - 基于现有 MySQL store / SQLite store 的接口，不直接操作 SQL
3. **登录门控**：同步模式启动时要求有效 XiaoZhi token（复用现有 SSO 校验）
4. **LLM 配置切换**：同步模式下发服务器 key 配置（settings 覆盖）
5. **设置页 UI**："数据存储"区块 + 迁移进度（前端）
6. **desktop 打包**：Electron 打包时默认不注入 MySQL 配置 → 出厂即本地模式

## 十、一句话总结

**默认本地（开源版体验，暂时免费引流），勾选即上云（商业版方案，收费点）**——
存储切换是现成的，主要工作是"一次迁移 + 登录门控 + 设置 UI"，工作量可控。
知识库与记忆始终留在本机，不参与同步。
